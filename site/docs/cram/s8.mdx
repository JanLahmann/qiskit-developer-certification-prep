## Structure types in OpenQASM 3 programs

### OpenQASM 3 is a typed language

OpenQASM 2 knew only two aggregate declarations: `qreg` and `creg`. OpenQASM 3 replaces them with a real type system: quantum registers become `qubit[n] name;`, classical registers become `bit[n] name;`, and a family of classical types joins them — sized integers (`int[32]`), floats (`float[64]`), `bool`, `complex`, `duration`, and more. Two things matter for the exam: first, what Qiskit *emits* (circuits export their registers as `bit[n]`/`qubit[n]`, loose clbits as bare `bit`); second, what Qiskit can *parse back* — the importer supports a subset of the type system, and the official feature table is the authority on which types survive the round trip (e.g. `duration` and `stretch` declarations are documented as unparseable).

*Sources: [qasm-feature-table](https://quantum.cloud.ibm.com/docs/guides/qasm-feature-table) · [qasm3](https://quantum.cloud.ibm.com/docs/api/qiskit/qasm3)*

**Key facts:**

- Qiskit exports classical registers as `bit[n] c;` even at width 1; loose `Clbit`s become bare `bit _bit0;`. — ⚙️ proven in [`s8-q010`](/docs/sections/s8)
- The feature table's Qiskit column documents `bit` as supported (mapped to `Clbit`/`ClassicalRegister`) while `duration` and `stretch` declarations are unparseable. — 📖 [qasm-feature-table](https://quantum.cloud.ibm.com/docs/guides/qasm-feature-table)
- An unbound `Parameter` exports to OpenQASM 3 as an `input float[64]` declaration — the circuit becomes a parameterized program. — ⚙️ proven in [`s8-q020`](/docs/sections/s8)
- The OpenQASM 3 classical types are `bool`, `int[n]`, `uint[n]`, `float[n]`, `complex[float[n]]`, `bit[n]`, `angle[n]`, `duration` and `stretch` — the last four being the 'special' types with no C equivalent. There is no `string`, `char`, `real` or `unsigned`, and a complex declaration takes a FLOAT type in its designator (`complex[float[64]] c;`), never a bare bit width. — 📖 [types.html](https://openqasm.com/versions/3.0/language/types.html)
- Casting rules: in a binary operation the LESSER type is promoted (`complex` &gt; `float` &gt; `int`/`uint`, wider beats narrower); `bool` and scalar `bit` are interchangeable as values; `bit[n]` converts to `int[m]`/`uint[m]`/`angle[m]` only when `m == n`; nothing casts to or from `duration` (divide by a duration instead); and a width designator must be a `const` expression. — 📖 [types.html](https://openqasm.com/versions/3.0/language/types.html)

## Interpret OpenQASM semantics

### Reading v2 and v3 programs side by side

The same circuit reads differently in the two versions: v2 opens with `OPENQASM 2.0;` and `include "qelib1.inc";`, declares `qreg q[2]; creg c[2];`, and measures with an arrow (`measure q[0] -> c[0];`). v3 opens with `OPENQASM 3.0;` and `include "stdgates.inc";`, declares `qubit[2] q; bit[2] c;`, and measures with an assignment (`c[0] = measure q[0];`). Control flow is the deepest semantic difference: v2 conditionals are limited to whole-register equality (`if (c == 1) ...`), while v3 has real `if`/`else`, loops, and per-bit conditions. Custom gates keep their `gate name ... { ... }` declaration in both versions — exports do not inline them.

*Sources: [interoperate-qiskit-qasm2](https://quantum.cloud.ibm.com/docs/guides/interoperate-qiskit-qasm2) · [interoperate-qiskit-qasm3](https://quantum.cloud.ibm.com/docs/guides/interoperate-qiskit-qasm3)*

**Key facts:**

- OpenQASM 2 conditionals accept only whole-register equality; exporting a per-clbit `if_test` raises `QASM2ExportError` ('OpenQASM 2 only supports register-equality conditions'). — ⚙️ proven in [`s8-q013`](/docs/sections/s8)
- v2 measures with `measure q[0] -> c[0];`, v3 with `c[0] = measure q[0];` — arrow vs assignment is a version tell in any printed program. — ⚙️ proven in [`s8-q014`](/docs/sections/s8)
- Custom gates round-trip as `gate mygate ... { ... }` declarations in both versions — neither exporter inlines them. — ⚙️ proven in [`s8-q019`](/docs/sections/s8)
- `qasm2.dumps` silently drops a circuit's global phase (v2 cannot express it); `qasm3.dumps` emits `gphase`. — ⚙️ proven in [`s8-q017`](/docs/sections/s8)

## Interoperate different versions of OpenQASM with Qiskit

### The four functions, and the one asymmetry that matters

Both `qiskit.qasm2` and `qiskit.qasm3` expose the same quartet: `dumps` (circuit → string), `dump` (circuit → file), `loads` (string → circuit), `load` (file path → circuit). The trap: `qasm3.loads`/`load` need the separate `qiskit-qasm3-import` package, while export and everything in `qasm2` are native to Qiskit. The old `QuantumCircuit.qasm()` method is gone in Qiskit 2.x, but the classmethods `from_qasm_str`/`from_qasm_file` still exist for OpenQASM 2. Exporters enforce language limits at export time: OpenQASM 2 cannot express a per-bit `if_test` condition or a global phase — the former raises `QASM2ExportError`, the latter is silently dropped.

*Sources: [qasm3](https://quantum.cloud.ibm.com/docs/api/qiskit/qasm3) · [qasm2](https://quantum.cloud.ibm.com/docs/api/qiskit/qasm2)*

**Key facts:**

- `qasm3.loads`/`load` raise `MissingOptionalLibraryError` unless `qiskit-qasm3-import` is installed; `qasm3.dumps`/`dump` and all of `qasm2` are native. — ⚙️ proven in [`s8-q021`](/docs/sections/s8)
- `qasm2.loads` accepts only the `OPENQASM 2.0;` header — feeding it a v3 program raises `QASM2ParseError` immediately. — ⚙️ proven in [`s8-q015`](/docs/sections/s8)
- `QuantumCircuit.from_qasm_str`/`from_qasm_file` still exist in Qiskit 2.x for OpenQASM 2 input; the instance method `.qasm()` was removed. — ⚙️ proven in [`s8-q012`](/docs/sections/s8)
- `dump` variants write to what you give them — `qasm2.dump(qc, stream)` takes an open text stream, `qasm2.load(path)` takes a filesystem path; mixing them up raises immediately. — ⚙️ proven in [`s8-q011`](/docs/sections/s8)

## Interact with the Qiskit IBM Runtime REST API

### Runtime over plain HTTPS

Everything the primitives do through Python can be done over REST. Authentication is two-step: exchange your IBM Cloud API key for an IAM bearer token (`POST` with the API-key grant type; tokens expire after 3600 seconds), then call the Runtime endpoints with that token plus a `Service-CRN` header identifying your instance. A primitive job is one request: `POST https://quantum.cloud.ibm.com/api/v1/jobs` with a body naming the `program_id` (`sampler` or `estimator`), the backend, and `params.pubs` carrying your (QASM-serialized) circuits.

*Sources: [cloud-setup-rest-api](https://quantum.cloud.ibm.com/docs/guides/cloud-setup-rest-api) · [sampler-rest-api](https://quantum.cloud.ibm.com/docs/guides/sampler-rest-api)*

**Key facts:**

- IAM token exchange: `POST` the IBM Cloud API key with the apikey grant type; the bearer token expires after 3600 seconds (`expires_in: 3600`). — 📖 [cloud-setup-rest-api](https://quantum.cloud.ibm.com/docs/guides/cloud-setup-rest-api)
- Submitting a Sampler job over REST is `POST /v1/jobs` with `'program_id': 'sampler'` and your circuits inside `params.pubs`. — 📖 [sampler-rest-api](https://quantum.cloud.ibm.com/docs/guides/sampler-rest-api)
- Every Runtime REST call after authentication carries two headers: the IAM bearer token and `Service-CRN` (the instance identifier — it is not itself a credential). — 📖 [cloud-setup-rest-api](https://quantum.cloud.ibm.com/docs/guides/cloud-setup-rest-api)
- Results are a sub-resource of the job: `GET /api/v1/jobs/{id}/results` returns the final result, while `GET /api/v1/jobs/{id}` returns details, `/logs` and `/metrics` return diagnostics, `POST /api/v1/jobs/{id}/cancel` cancels and `DELETE /api/v1/jobs/{id}` removes a job already in a terminal state. — 📖 [jobs](https://quantum.cloud.ibm.com/docs/api/qiskit-runtime-rest/tags/jobs)
